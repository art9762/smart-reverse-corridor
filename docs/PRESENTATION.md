# Презентация для жюри (5 минут)

Цель — за 5 минут показать жюри, что **проблема настоящая**, **наше решение работает**, и **мы понимаем, что делать дальше**.

Структура жёстко привязана ко времени. Если демо ломается — переключаемся на план Б из [`RISKS.md`](RISKS.md).

Текст для спикера с тайм-кодом — [`PITCH_OUTLINE.md`](PITCH_OUTLINE.md).
Демо-сценарий — [`DEMO.md`](DEMO.md).

## Слайды

### 1. Заглушка/команда
Название, команда, кейс «Цифровая Эра Транспорта 2026».

### 2. Проблема в одном кадре
Фото типичного реверсивного участка + 3 пункта:
- лобовые ДТП при преждевременной смене фазы;
- очереди в час пик;
- простой пустой полосы.

### 3. Наше решение в одной схеме
Диаграмма из `README.md`: камеры → ML → MQTT → контроллер (FSM) → дашборд. Подпись: «зона ремонта пустая → переключаем».

### 4. Демо: baseline
Скрин/видео симулятора с фиксированным таймером, асимметричный поток. Большая красная очередь.

### 5. Демо: adaptive
Тот же поток, наш контроллер. Очередь рассасывается. Подсветить состояние FSM.

### 6. Демо: безопасность
Фура застряла, alert красный, фаза НЕ переключается. Это ключевое отличие от «просто датчиков».

### 7. Цифры
Сравнительный график throughput / queue / delay. Источник — `scripts/plot_results.py`.

### 8. Метрики безопасности
Количество преждевременных смен фазы за прогон. Время реакции на спецтранспорт.

### 9. Что дальше
- Пилот: один реверсивный участок длиной до 1 км.
- Интеграция: вход в существующий АСУДД через MQTT/REST.
- Edge: Jetson Orin Nano, YOLOv8n int8.
- Дорога: расширение на регулируемые перекрёстки.

### 10. Спасибо / вопросы
QR на репозиторий, контакты.
