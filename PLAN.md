# Оставшиеся задачи «Умного реверсивного коридора»

Актуализировано 23 октября 2026 года по исходникам и выполненным проверкам. Это план
программного прототипа и симуляции. Проект не прошёл проверку пригодности для управления
реальными светофорами; проценты «безопасности» и готовности не используются.

## Подтверждённое состояние

- Локально на Python 3.11 проходят 54 теста контроллера, 22 симулятора и 16 ML/CV;
  ML-тесты также проходят в чистом Python 3.12 с `requirements-test.txt`.
- [CI программного изменения](https://github.com/art9762/smart-reverse-corridor/actions/runs/39945864808)
  завершился успешно: Python 3.11/3.12 для трёх сервисов, web-тесты/сборка, Compose config
  и сборки четырёх Docker-образов. Сборка образа не подтверждает работу запущенного стека.
- Недавние повторы camera events отбрасываются до изменения счётчиков, метрик и журнала;
  [контракт MQTT](docs/MQTT.md) описывает UUID, совместимость и пределы кэша.
- Выполнены 30 секунд headless-симуляции без брокера и офлайн-проверка цепочки
  «виртуальная камера → JSON/тема MQTT → контроллер» с повторной доставкой выхода.
- В коде уже есть `mode_switch`, `/test/reset`, панели сравнения/задержки, HTML-презентация
  и скрипты ML-демо. Они не считаются проверенными end-to-end только по наличию файлов.

## Приоритеты и критерии завершения

| Приоритет | Оставшаяся задача и основание | Критерий завершения |
|---|---|---|
| P0 | Согласовать обработку потери камер с заявленным инвариантом FSM. [Fallback в engine](services/controller/app/engine.py) временно подменяет проверку пустоты зоны, а [MQTT heartbeat tracking](services/controller/app/mqtt_client.py) отмечает получение heartbeat независимо от `healthy: false`. | Отдельные сценарии симуляции покрывают одну/две потерянные камеры, отрицательный heartbeat, занятую/неизвестную зону и восстановление. Выбранная политика явно описана; документация не приписывает fallback проверку, которую код обходит. Заявленный инвариант подтверждён тестами для всех включённых режимов. |
| P1 | Уточнить смысл метрик. [Контроллер](services/controller/app/engine.py) выдаёт occupancy как `queue`, считает `avg_delay` по времени между въездом и выездом и хранит последние 500 задержек без временных меток. | На детерминированном сценарии отдельно сверены очередь до въезда, occupancy, ожидание и время проезда; метрики с суффиксом `5min` исключают устаревшие значения после 300 секунд. Графики и подписи используют те же определения. |
| P1 | Довести интеграционный стенд. [Fixtures](tests/integration/conftest.py) ссылаются на `infra/docker-compose.yml` и `services/controller/main.py`, тогда как Compose находится в корне, а приложение — в `app/main.py`. | Изолированный брокер и контроллер стартуют по актуальным путям; [integration suite](tests/integration) выполняется без неожиданных skip. Проверены MQTT → controller → WS/UI, переключение режима, приоритет и отказ камеры только на программном стенде. |
| P1 | Проверить подтверждение override в UI. [Клиент](web/src/api/client.ts) не проверяет поле `ok` ответа, хотя [engine](services/controller/app/engine.py) может вернуть `ok: false` при HTTP 200. | Отказ в смене фазы показывается как отказ, а успешная команда подтверждается фактическим состоянием; есть тесты для отказа guard, emergency/resume и переключения режима. |
| P1 | Получить воспроизводимое сравнение baseline/adaptive после исправления определений метрик. [Генератор sample results](scripts/generate_sample_results.py) использует отдельную упрощённую модель, а не реальный engine. | Сохранены конфигурация, seed, длительность, CSV и графики из [bench runner](scripts/bench.py) на работающем изолированном стеке. Sample-данные помечены отдельно и не используются как доказательство выигрыша текущего контроллера. |
| P1 | Сделать проверки качества обязательными. [CI](.github/workflows/ci.yml) ещё подавляет ошибки Ruff, а [Makefile](Makefile) маскирует неуспех pytest сообщением `no tests`. | Намеренно сломанные lint/test завершают соответствующие команды ошибкой; существующий долг устранён или явно ограничен конфигурацией. Health checks и demo launcher не выдают недоступный сервис за готовый. |
| P2 | Проверить ML и презентацию на воспроизводимых материалах. Записан программный demo fallback, а [презентация](docs/presentation.html) показывает измеренные результаты и ограничения. Персональные видео и камеры без разрешения не используются. |

## Границы текущей проверки

Кэш повторов хранит до 10 000 событий в течение 10 минут и очищается при рестарте/reset.
Это не durable exactly-once: старый отправитель, повторяющий ту же комбинацию track/time
после рестарта, может столкнуться с прежним ключом. Полный запущенный Docker/MQTT/Influx/Grafana
конвейер, качество YOLO на реальном видео и эксплуатация не проверялись в этой доработке.
Успех unit-тестов не заменяет эти проверки.

ONNX/TensorRT, новые сценарии и публикация release-образов — последующие отдельные задачи.
[Release workflow](.github/workflows/release.yml) пока намеренно отключён. Подключение дорожного
оборудования, эксплуатационное развёртывание и заявления о предотвращении ДТП в этот план не входят.
